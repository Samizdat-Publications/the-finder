# M2: Engines and scaffold

_Draft written by the lead during M1 (build session 2, 2026-10-15); finalized at the M1 gate._

**Goal:** the engines the game stands on, proven in a real browser, plus the site skeleton and a first
preview deploy. At the end: the browser decoder in a Worker reproduces the reference decoder; the
record's audio and picture signal ship as per-track and per-frame files; a turntable engine plays the
record at right and wrong speeds and directions; a Vite site with `/`, `/play/` and `/checked/` is live
at `https://the-finder.stewartgregerson.workers.dev` with a bare instrument on `/play/` (drop the needle,
hear the record, watch a picture decode).

**Read first:** `PLAN.md` ("Architecture", chapters 5 and 6, "How it's checked" items 8 and 9),
`docs/research/images-and-audio.md` sections 1, 4 and 5, `HANDOFF.md` gotchas (browser audio,
Cloudflare Range, wrangler and spaces in paths, npx.cmd), `tools/ref-decoder/README.md` (the measured
geometry the browser must match).

## Facts from the scout (2026-10-15)

- Versions (npm): vite 8.3.4 (7 days old; 8.2.4 and 8.1.6 from 2026-10-06), @preact/preset-vite 2.10.6,
  preact 11.0.1 (major 11.0.0 is two weeks old; check whether 10.x latest is the safer pick with
  @preact/signals 2.11.3), three 0.186.1 and @types/three 0.186.0, playwright 1.64.x, wrangler 4.151.0
  (4.147.0 from 2026-10-02 is older). Vite 8 uses Rolldown (`build.rolldownOptions`), needs Node 20.19+
  (we run 24.19), works with Vitest 5.0.5 (peer `vite ^6.4 || ^7 || ^8`). Pin exactly.
- Cloudflare static assets: `wrangler.jsonc` with `name`, `compatibility_date`, `assets.directory`
  `./dist`, no `main`. Default `html_handling` (`/play/` serves `dist/play/index.html`); do not use SPA
  `not_found_handling`. 25 MiB per file, 20,000 files. Range requests still ignored (fetch whole files).
  Content types for `.flac` / `.opus` / `.webm`: check with `curl -I` after the first deploy; override in
  `_headers` if wrong.
- Web Audio: `AudioContext`, `OfflineAudioContext` and `decodeAudioData` are Window-only (not in
  Workers): decode on the main thread, transfer the `Float32Array` to the decoder Worker. 96,000 Hz is
  inside the spec's required `OfflineAudioContext` range; a 96 kHz file decoded there is not resampled
  (spec-implied: assert the decoded length equals the slice's sample count).
- **Opus always decodes at 48 kHz**, so picture slices must be FLAC (or WAV) at 96 kHz. Music: Opus
  (Ogg or WebM) at about 160 kbps for Chrome, Edge and Firefox; probe `decodeAudioData` support per
  codec in Playwright (Chrome, Firefox, WebKit) before choosing; AAC `.m4a` is the Safari-safe fallback.
- `AudioBufferSourceNode.playbackRate` shifts pitch with speed; negative rates are not relied on
  (pre-render reversed buffers).

## Steps

0. [x] Decisions: side break after music #11, shown as an inference (D-A17); picture slices FLAC 96 kHz
   16-bit mono, music Opus about 160 kbps, container from the probe (D-A18). Fixtures: the FLAC picture
   slices are committed runtime media, so the Python reference can re-decode them (its 96 kHz path)
   into `build/ref96/` on a fresh clone without the 1.46 GB tape; the browser decoder is tested against
   those decodes. Record audio sources downloaded and MD5-verified (`ozma-cd-01` to `-31`).
1. [ ] Scaffold and harness (`builder`, spec `docs/plans/M2_specs/step1-scaffold-harness.md`): Vite
   multi-page (`/`, `/play/`, `/checked/` rendering How it's checked), Preact, boot-error overlay,
   `wrangler.jsonc`, `npm run dev|build|preview|deploy|capture|probe:audio`, `Play The Finder.bat`,
   check step "Site build", hygiene over `public/` and `dist/`, Playwright harness with installed Chrome,
   the audio-codec probe.
2. [ ] Media pipeline (`asset-smith`): per-track Opus transcodes into `public/media/audio/` (each under
   20 MB) plus the picture side's listening track from the tape (stereo, 48 kHz); the 156 FLAC picture
   slices from `build/slices/` into `public/media/frames/` with a lossless round-trip check (decoded
   samples identical to the WAV slices); `data/record.json` (both sides, track order, titles,
   performers and credits, durations, file, bytes, SHA-256; the side break as an inference field) and
   `data/frames.json` (from `build/slices/index.json` and the image list: frame, channel, image number,
   colour role, first-line offset, sample count). Credits per track in `docs/CREDITS.md`.
3. [ ] Browser decoder (`builder-opus`): `src/dsp/` port of `tools/ref-decoder` at 96 kHz (pure:
   Float32Array in, pixels out; every parameter explicit, including wrong ones: line time, interlace,
   sync lock on or off, droop tau per channel, clamp smoothing, polarity, aspect rows), a Worker
   wrapper, and a main-thread loader (fetch FLAC, `decodeAudioData` in an `OfflineAudioContext` at
   96,000 Hz, assert the length, transfer to the Worker). Tests: Node decodes of the slices (via a WAV
   copy made with ffmpeg into `build/`, SKIP with a clear line when ffmpeg is missing) match the Python
   96 kHz reference with SSIM at least 0.98 per frame; the circle's axis ratio 1.00 +/- 0.01; the wrong
   line times give the slants in `build/ref/metrics.json` within 10%; a Playwright test decodes a few
   frames through the real browser path and matches too.
4. [ ] Turntable engine (`builder-opus`): `src/record/` timeline (needle radius to side, track and time;
   constant groove pitch at 16 2/3 rpm; the cover's 3.6 s per turn) and the Web Audio engine
   (AudioBufferSourceNode with `playbackRate` = speed ratio, pre-rendered reversed buffers for the wrong
   direction, stylus drop and run-out sounds synthesized, whole-file fetch with progress). Node tests
   for the timing math; Playwright `OfflineAudioContext` tests: a speed error of k shifts a test tone's
   measured frequency by exactly k (within 0.1%) and time-compresses by k; the wrong direction plays
   the buffer reversed.
5. [ ] The bare instrument on `/play/` (`builder`): needle, speed and direction controls on the real
   record; a picture decoding live from its slice in the Worker, line by line, with line-time,
   interlace and sync-lock knobs; honest labels. Not the game interface (M3).
6. [ ] Captures (`npm run capture`), the lead looks at them; `player-critic` is not needed until M3.
7. [ ] Deploy (`npm run deploy`), check content types with `curl -I`, send Stewart the link.
8. [ ] Gate: `npm run check` green; `qa-auditor`; commit, push, PROGRESS and HANDOFF; write
   `docs/plans/M3.md` and continue.
