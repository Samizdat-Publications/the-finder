# M2: Engines and scaffold

_Draft written by the lead during M1 (build session 2, 2026-10-15); finalized at the M1 gate._

**Goal:** the engines the game stands on, proven in a real browser, plus the site skeleton and a first
preview deploy. At the end: the browser decoder in a Worker reproduces the reference decoder; the
record's audio and picture signal ship as per-track and per-frame files; a turntable engine plays the
record at right and wrong speeds and directions; a Vite site with `/`, `/play/` and `/checked/` is live
at `https://the-finder.stewartgregerson.workers.dev` with a bare instrument on `/play/` (drop the needle,
hear the record, watch a picture decode).

**Read first:** `PLAN.md` ("Architecture", chapters 5 and 6, "How it's checked" items 8 and 9),
`docs/research/images-and-audio.md` sections 1, 4 and 5, `HANDOFF.md` gotchas (browser audio,
Cloudflare Range, wrangler and spaces in paths, npx.cmd), `tools/ref-decoder/README.md` (the measured
geometry the browser must match).

## Facts from the scout (2026-10-15)

- Versions (npm): vite 8.3.4 (7 days old; 8.2.4 and 8.1.6 from 2026-10-06), @preact/preset-vite 2.10.6,
  preact 11.0.1 (major 11.0.0 is two weeks old; check whether 10.x latest is the safer pick with
  @preact/signals 2.11.3), three 0.186.1 and @types/three 0.186.0, playwright 1.64.x, wrangler 4.151.0
  (4.147.0 from 2026-10-02 is older). Vite 8 uses Rolldown (`build.rolldownOptions`), needs Node 20.19+
  (we run 24.19), works with Vitest 5.0.5 (peer `vite ^6.4 || ^7 || ^8`). Pin exactly.
- Cloudflare static assets: `wrangler.jsonc` with `name`, `compatibility_date`, `assets.directory`
  `./dist`, no `main`. Default `html_handling` (`/play/` serves `dist/play/index.html`); do not use SPA
  `not_found_handling`. 25 MiB per file, 20,000 files. Range requests still ignored (fetch whole files).
  Content types for `.flac` / `.opus` / `.webm`: check with `curl -I` after the first deploy; override in
  `_headers` if wrong.
- Web Audio: `AudioContext`, `OfflineAudioContext` and `decodeAudioData` are Window-only (not in
  Workers): decode on the main thread, transfer the `Float32Array` to the decoder Worker. 96,000 Hz is
  inside the spec's required `OfflineAudioContext` range; a 96 kHz file decoded there is not resampled
  (spec-implied: assert the decoded length equals the slice's sample count).
- **Opus always decodes at 48 kHz**, so picture slices must be FLAC (or WAV) at 96 kHz. Music: Opus
  (Ogg or WebM) at about 160 kbps for Chrome, Edge and Firefox; probe `decodeAudioData` support per
  codec in Playwright (Chrome, Firefox, WebKit) before choosing; AAC `.m4a` is the Safari-safe fallback.
- `AudioBufferSourceNode.playbackRate` shifts pitch with speed; negative rates are not relied on
  (pre-render reversed buffers).

## Steps (to be finalized at the M1 gate)

0. Decisions (logged in `docs/DECISIONS.md`): the record's side break (after music #9, #11 or #12; show
   as an inference), the music codec (from the probe), the picture-slice format (FLAC 96 kHz 16-bit
   mono, from `build/slices/`), what reference fixtures get committed so `npm run check` is meaningful on
   a fresh clone.
1. Scaffold (`builder`): Vite multi-page (`index.html`, `play/index.html`, `checked/index.html`),
   Preact, strict TS, boot-error overlay, `wrangler.jsonc`, `npm run dev|build|preview|deploy`,
   `Play The Finder.bat`, hygiene extended to `dist/` sizes.
2. Media pipeline (`asset-smith`): Ozma CD rip (Internet Archive `voyager-golden-record-cd-ozma`, 31
   FLACs with published MD5s) into `sources/ozma-cd/`; per-track transcodes into `public/media/audio/`;
   the picture side's listening audio from the tape; the 156 FLAC picture slices into
   `public/media/frames/`; `data/record.json` (timeline of both sides) and `data/frames.json` (slice
   index, image numbers, colour roles); every file under 20 MB; lossless round-trip checks.
3. Browser decoder (`builder-opus`): `src/dsp/` port of the reference decoder (pure; Float32Array in,
   pixels out; all parameters explicit, including the wrong ones), Worker wrapper; tests against the
   reference decodes (SSIM at least 0.98), the circle's axis ratio, the wrong-result slants within 10%
   of prediction.
4. Turntable engine (`builder-opus`): `src/record/` timeline (needle position to track and time, both
   sides) and the Web Audio engine (speed, direction, stylus drop, whole-file fetch with progress);
   Node tests for the timing math; Playwright `OfflineAudioContext` tests: a speed error of k moves the
   measured pitch by exactly k; the wrong direction reverses the audio.
5. The bare instrument on `/play/` (`builder`): needle, speed and direction controls; a picture decoding
   live from its slice in the Worker with line-time and interlace knobs.
6. Harness (`builder`): Playwright with installed Chrome (adapt Cut & Fill `tools/harness/`), captures
   into `review/inbox/`; landing page stub with honest text.
7. Deploy (`npx wrangler deploy` from the project folder), check content types, send Stewart the link.
8. Gate: checks green; the lead looks at captures; `qa-auditor`; commit, push, PROGRESS and HANDOFF;
   write `docs/plans/M3.md` and continue.
