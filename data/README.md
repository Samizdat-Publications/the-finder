# data/: the real data, built from sources

Every file here is generated by `tools/data/` from raw sources in `sources/` (fetched and checksummed
by `tools/fetch-sources.mjs`, listed in `tools/sources.json`). Never edit these files by hand.
Rebuild everything and run the checks with:

```powershell
cd "C:\Users\stewa\Documents\Claude\Golden Record"; python -P tools/data/build_all.py
```

Output is deterministic: keys sorted, floats written with Python's shortest round-trip form (full double
precision). Only `meta.built` (the build date) changes from day to day.

Conventions: angles in degrees; `null` means "not given by the source". MJD is Modified Julian Date
(UTC day for the Crab file, TT-based catalogue epochs for ATNF); JD in the ephemeris is TDB.

## cover.json (`build_cover.py`)

Every etched number on the Voyager record cover. Hydrogen time unit t_H = 1 / 1,420,405,751.768 Hz
= 0.70402418 ns (docs/research/cover.md "Units").

- `record.rotationPeriod`, `record.playTime`, `picture.lineTime`, `picture.rasterLines`, and each of
  `picture.lineLabels[]`: `{ binary, bits, valueTH, meaning, location, provenance }`. `valueTH` is the
  exact integer value of `binary` (all fit below 2^53). Units are t_H, except `rasterLines` and
  `lineLabels` (plain counts). Strings are the research's pixel-scan transcription of NASA photo
  GPN-2000-001978 (cover.md 1b, 1c), matching Dack and CED Magic. `picture.notes` records the disputed
  small raster label (1/10/11 or 16) as a note, not a value.
- `pulsarMap.gcLine`: `{ lengthSvg, angleDeg: 0, svgAzimuthDeg, endTickLengthSvg, meaning, provenance }`.
  `lengthSvg` = R0 (origin to the centre line's end tick) in SVG units of the Pioneer plaque trace;
  `svgAzimuthDeg` is the drawn centre line's raw azimuth in the SVG (0.099 deg), the zero of every
  `mapAngleDeg`.
- `pulsarMap.lines[]` (14, counter-clockwise map order): `{ order, label1972, bname, jname, binary, bits,
  valueTH, mapAngleDeg, svgAzimuthDeg, rOverR0, absZOverR0, broken, breakR0, digitsAlongOwnLine, notes,
  provenance }`.
  - `mapAngleDeg`: counter-clockwise from the drawn galactic-centre line, as the map defines it
    (equals galactic longitude, cover.md 1d): `svgAzimuthDeg - gcLine.svgAzimuthDeg`.
  - `svgAzimuthDeg`: the line's raw azimuth from the SVG +x axis (counter-clockwise, SVG y flipped):
    the median azimuth of its stroke midpoints beyond 60 SVG units from the origin (beyond the breaks).
  - `rOverR0`: solid-line length (in-plane distance d cos b) over R0. `absZOverR0`: outer end of the
    solid line back to its tick, over R0 (sign not encoded); `null` for B1929+10 and B0950+08 (no tick).
  - `breakR0`: the gap `[start, end]` over R0, or `null` for unbroken lines (Crab, B1929+10, B0950+08).
  - `binary`: most significant bit nearest the origin. B1240-64's digits run beside its own line.
  - Identity: each line's decoded integer matched to Sagan, Salzman Sagan and Drake 1972 Table 1.
- `meta.svgUnits.origin`: the map origin used, our least-squares intersection of the long radial
  strokes (`svgmap.find_origin`); `originResearch`: the research digitization's undocumented origin,
  0.55 units away (0.0003 R0), for reference only. Against the research's angles the published ones
  differ by up to 0.22 deg (B0950+08): the origin difference turns short lines by up to 0.12 deg, and
  the research measured from SVG +x rather than the drawn centre line (0.099 deg).

## pulsars.json (`build_pulsars.py`)

All 4,503 pulsars of ATNF v2.9.0, one per line, sorted by J name. Every field below is always
present (null when unknown) except `pxErr`, `pmraErr` and `pmdecErr`, which are omitted when null to
keep the file under 2 MB.
`{ meta: { catalogue, count, citation, source, built, units, notes }, pulsars: [ ... ] }`, each pulsar:

| Field | Unit | Notes |
|---|---|---|
| jname, bname | | bname null when the pulsar has no B name |
| p0 | s | from P0, or 1/F0 |
| p1 | s/s | from P1, or -F1/F0^2 |
| f0, f1, f2, f3 | Hz, Hz/s, Hz/s^2, Hz/s^3 | f0 from F0 or 1/P0; f1 from F1 or -P1/P0^2; f2, f3 only as stored |
| f0Err, f1Err | Hz, Hz/s | 1-sigma: quoted uncertainty times the last quoted digit; when derived from P, propagated as psrcat does (sigma_F0 = sigma_P0/P0^2; sigma_F1 = hypot(sigma_P1/P0^2, 2 P1 sigma_P0/P0^3)) |
| pepoch | MJD | epoch of the spin parameters |
| dm | pc cm^-3 | |
| dist | kpc | catalogue "best" distance, psrcat's own rule (below) |
| distDm | kpc | DIST_DM, YMW16 electron-density model |
| px | mas | parallax |
| ra, dec | deg | from RAJ/DECJ; for the 241 pulsars with only ELONG/ELAT, converted from ecliptic J2000 (obliquity 84381.448 arcsec) |
| gl, gb | deg | computed from ra, dec with the Hipparcos ICRS-to-galactic matrix (ESA 1997 vol. 1 section 1.5.3) |
| pmra, pmdec | mas/yr | pmra includes cos dec; ecliptic proper motions rotated when only PMELONG/PMELAT exist |
| pxErr | mas | 1-sigma parallax error; **key absent when the catalogue has none (absent = null)** |
| pmraErr, pmdecErr | mas/yr | 1-sigma; for ecliptic-only pulsars the diagonal errors are rotated (correlation not stored); **absent = null** |
| nglt | count | number of glitches the catalogue lists (NGLT) |
| assoc | | ASSOC string as stored |
| binary | bool | true when the record has BINARY, PB, FB0 or A1 |

`dist` rule (psrcat `defineParams.c`, `defineDistance`, read from the shipped source): DIST_A if
present; else 1/PX when PX is more than 3 sigma; else, when DIST_AMN and DIST_AMX exist, DIST_DM if it
lies between them, otherwise the nearer limit (their midpoint if there is no DIST_DM); else DIST_DM.
The 14 map pulsars reproduce clocks.md Table 2B exactly.

## glitches.json (`build_timing.py`)

Jodrell Bank glitch catalogue for the 14 map pulsars, keyed by J name (empty list = no glitches).
Each glitch: `{ n, mjd, mjdErr, dfOverF, dfOverFErr, df1OverF1, df1OverF1Err, ref }`. `dfOverF` and
`df1OverF1` are plain dimensionless numbers (the table prints them in 1e-9 and 1e-3); `null` where
the table prints X.

Jodrell Bank Crab monthly ephemeris, all 482 rows, sorted by MJD. Columns are documented in

## stars.json and sky.json (`build_stars.py`)

HYG v4.2 plus Gaia DR3 for Gliese 445. Frame: ICRS, solar-system barycentre; the Sun is id 0 at the
origin with zero velocity.

- `stars.json`: `{ meta, near }`. `near`: the Sun plus every star with 0 < dist <= 30 pc, one object
  per line, sorted by distance.
- `sky.json`: `{ meta, columns, rows }`: stars with mag <= 6.5 that are not in `near` (dist > 30 pc or
  unknown), sorted by id. `columns` names the fields (the same as `near`); each row is one star's
  values in that order.

Fields: `id` (HYG id), `name` (proper name or null), `gl`, `hip`, `hd`, `raDeg`, `decDeg` (at
`epoch`), `distPc` (null when HYG has 100000 = unknown), `pmraMasYr` (includes cos dec: HYG's own
vx, vy, vz for Gliese 445 are reproduced only with that reading), `pmdecMasYr`, `rvKmS`, `mag`,
`absmag`, `spect`, `ci`, `astrometrySource` ("hyg" or "gaia-dr3"), `epoch` (decimal year: 2000.0 for
HYG, 2016.0 for Gaia DR3).

- `rvKmS`: HYG stores 0.0 when no radial velocity is known, so 0.0 is stored as null (a true value of
  exactly 0.0 at HYG's 0.1 km/s resolution would be lost).
- Companions: a star without a radial velocity whose system primary (HYG `comp_primary`) has one takes
  the primary's; near stars so filled carry `rvFromPrimary: true` (187 of them, Sirius B and Procyon B
  among them). A bound companion moves with its system to within its orbital speed (a few km/s), far
  below the trail's tens of km/s. Systems whose primary has none (GJ 1245 A and B) stay null.
- Stars with `astrometrySource: "gaia-dr3"` (Gliese 445) also carry `gaiaDr3SourceId`, `parallaxMas`
  and the Gaia 1-sigma errors `parallaxErrMas`, `pmraErrMasYr`, `pmdecErrMasYr`, `rvErrKmS`; `distPc`
  = 1000 / parallax. HYG has no errors, so these fields are absent on HYG rows.

## ephemeris.json and ephemeris_spotchecks.json (`build_ephemeris.py`)

JPL Horizons vectors, ICRF axes, centred on the Sun (500@10), km and km/s, TDB.
`bodies["-31"|"-32"]`: Voyager 1 and 2, 30-day nodes from JD 2451544.5 (2000-01-01) to the last node
inside Horizons coverage (1,218 rows, last 2099-12-17); `bodies["399"]`: Earth, 10-day nodes
2020-2040. Each `{ jd0, stepDays, rows: [[x, y, z, vx, vy, vz], ...] }`, row i at jd0 + i * stepDays.
Interpolate with cubic Hermite on position and velocity (max error 1.75 km against the spot checks).
`ephemeris_spotchecks.json`: `checks[]` of `{ body, jd, x, y, z }`, 24 off-node epochs per craft
(every 4.17 years from 2001.3, at odd hours TDB), each fetched from Horizons directly.

## scenario.json (`build_scenario.py`)

The story config: craft Voyager 1 with its asymptote (Bailer-Jones and Farnocchia 2019) and a
Horizons reference state relative to the solar-system barycentre at 2026-10-15 19:00 TDB
(`craft.stateRef`), home star Gliese 445 (Gaia DR3 source_id, HYG id), the discovery rule, and the
Voyager 2 / Ross 248 alternative. The discovery epoch is not stored: the science core computes it.

## seeds.json (`tools/seeds/build-seeds.mjs`)

The playthrough seeds "Start over" takes (D-A28; `src/game/seeds.ts`, cycling through the list in order). Built
by playing each candidate seed `finder-2`, `finder-3`, ... in order with every seed-reading checker's right
answer (`src/chapters/seedCheck.ts` verifySeed: the game's own code, loaded through Vite's module runner, on
the answers the instruments lead to, measured values and never the simulation's truth) and listing the seeds
where all of them confirm. Deterministic: no dates or timings in the file. About 8 minutes on 15 worker
processes for 2,000 candidates:

```powershell
cd "C:\Users\stewa\Documents\Claude\Golden Record"; node tools/seeds/build-seeds.mjs
```

`{ meta, seeds }`. `seeds[]`: the listed seeds. `meta`: `candidates`, `firstCandidate`, `lastCandidate`,
`listed`; `excluded` `{ total, byCheck: { deduction id: seeds }, seeds: [{ seed, failed: [{ id, message }] }] }`;
`rates`: over all candidates, how often the warm-white star (the true origin) lands beyond trail.origin's 95%
and 99.9% cuts and outside the map region's 95% and 99.9% contours (`trailWhereContourMax`: the largest
contour reached), and how often a pure start is refused on a one-day count (the counts' fitted start is then
proposed, and confirms). `src/chapters/seedCheck.test.ts` replays the default seed, five listed seeds and one
excluded seed per reason on every `npm run check`. Rebuild after any change to a checker, the epoch model or
the data they read.

## teaching.json (`tools/data/build_teaching.py`)

The teaching pictures' readable cells for The Pictures (M5 step 3): for each of L002 (numerals), L003 (units),
L004 and L005 (the planets) and L039 (the two heights), the regions of the decoded frame (536 x 355, the
reference decode in `build/ref/frames/`) that hold each symbol, number or table cell, and the value each
holds. Regions are measured, not guessed: the tight box (padded 2 px) round the dark connected components
inside a coarse layout window, ink being darker than 0.72 of the window's median grey. Values are the
readings in `docs/research/teaching-frames.md`, cited per entry. The builder checks two readings itself (the
dot rows of L002 count 1 to 6 as ink blobs; each digit cell holds one character and the ten row two), and
`src/science/teaching.test.ts` (`teaching.regions`) checks that every region holds ink on the browser's own
decode (pixel-identical to the reference, D-A30).

## voices.json (`tools/voices/analyse.py`)

The Voices' reference analysis (M5 step 4) of the lossless Ozma transfers (`sources/ozma-cd-NN/NN.flac`), each
track as its mono mix (L + R) / 2 rounded to 16 bits; the same samples go to `build/voices/NN.wav` (gitignored)
so the Node tests can run the TypeScript on them (`src/dsp/voices.ref.test.ts`). The four Voices checkers judge
against these numbers; `tools/voices/checks.py` checks them against `docs/research/voices.md`, synthetic tones
and synthetic melodies. Methods and settings: `tools/voices/vdsp.py` and `vmusic.py` (twins of
`src/dsp/segment.ts`, `pitch.ts`, `spectrum.ts`). About 1.5 minutes; the bootstraps use fixed seeds.

```powershell
cd "C:\Users\stewa\Documents\Claude\Golden Record"; python -P tools/voices/analyse.py; python -P tools/voices/checks.py
```

- `meta.yin`: the YIN threshold (0.1), 10 ms frames, the quiet-frame cut (-60 dBFS) and the tracker settings
  (Hz, window in s) for speech, calls, the violin and the aria. `meta.notes`, `snrEdgeDb`, `crossingTopHz`.
- `greetings` (Ozma 02): `levelsDb10` (each 10 ms frame's level in tenths of a dBFS, a full-scale sine at 0;
  -2000 for digital silence), `f0Hz100` (pitch per frame in hundredths of a Hz, 0 unvoiced); `researchTable`
  (silent runs on voices.md section 1's grid, and the research's own numbers); `levelMixture` (two Gaussians fitted
  to the frame levels: the noise between voices and the voices); `reasonable` (thresholds where a frame is the
  noise with probability 0.95 down to 0.05, and gaps 0.15 to 0.4 s from voices.md); `accepted` (the fewest and
  most segments over those settings); `speechCeilingHz` (the highest median pitch of any pitch run held 0.2 s);
  `oneSpeaker` (Ozma 01, Waldheim: frames, pitch, and the sd of his segment pitches in semitones at the
  centre of the reasonable settings); `reference` (at that setting: segments, their pitch sd, voices' worth of
  pitch, the F-test against one speaker, and BIC for 1, 2 and 3 Gaussian groups minus that for 1).
- `spectrum`: 250 Hz bands to 22.05 kHz (`bandEdgesHz`), Welch settings, `perTrackDb` and `aggregateDb` (every
  speech and music track, 01, 02 and 05 to 31, for display), `greetingsDb` and `noiseDb` (the greetings and their
  own silences: stretches below the reasonable threshold's low end, long enough for one Welch segment),
  `crossingHz` (where the greetings fall to twice the noise's power, judged up to 20 kHz) with its 95%
  `crossingBandHz` (block bootstrap over Welch segments), and the 95%-of-power frequencies.
- `music.violin` (Ozma 14, the Gavotte): `notes` `[start frame, frames, cents re 440 Hz x 100]`, `octaveCents`
  (the repetition curve's peak nearest a doubling), its bootstrap half-width, the tracker's 95% error on
  synthetic tones, and the 100-cent grid resultant. `music.aria` (Ozma 15): the same grid resultant, showing why
  the aria was not used. `music.piano` (Ozma 21, Gould): `hist` (spectral-peak magnitude per 5-cent bin over
  +/- 3600 cents, sum 1), `combScores` (k = 2 to 36 equal steps per octave), `combK`, the fit, and the block
  bootstrap's share of draws picking the same comb.
- `whale` (Ozma 03): `calls` `[start frame, frames, median Hz, glide cents]` (pitch runs held 0.2 s with a
  median above `speechCeilingHz`) and `segmentS`, the stretch from the first call to the end of the last.
